# Publishing

One version covers the whole repository: `pyproject.toml`, the root
`Cargo.toml` (`[workspace.package] version` and the `instrukt-ai-logging` pin
in `[workspace.dependencies]`), `uv.lock` and `Cargo.lock`.
`python3 .github/scripts/version.py check` verifies they agree. A release
publishes three things for one tag `vX.Y.Z`:

- **GitHub Release**: `instrukt-ai-logs` and `instrukt-ai-log-setup` binaries
  for aarch64/x86_64 macOS and x86_64/aarch64 Linux (gnu), per-archive
  `.sha256` files plus `sha256.sum`, and the shell installer
  `instrukt-ai-logs-installer.sh`.
- **crates.io**: `instrukt-ai-logging` (writer crate), then `instrukt-ai-logs`
  (the tool).
- **PyPI**: `instruktai-python-logger` (the Python writer SDK).

## Workflows

- `ci.yml` checks every pull request, and is the checks of a release:
  actionlint, the version agreement check, the Python gates (ruff, pyright,
  mypy, pytest), the Rust gates on Linux and macOS (fmt, clippy, tests,
  `cargo package`), dist builds for every target and a shell-installer smoke
  test.
- `auto-release.yml` (`Release (Auto)`) runs on every push to `main`. Its
  jobs:
  - `gate` decides the mode. `release` when there are commits since the last
    tag; `resume` when HEAD is the last tag's release commit but that tag has
    no GitHub Release; nothing to do when HEAD is released and its GitHub
    Release exists.
  - `inspect` (release mode): the release inspector
    (`anthropics/claude-code-action`, instructions in
    `.github/prompts/release-inspector.md`) reads the changes since the last
    tag against the public contract and returns the semver bump and the
    release notes (uploaded as the `release-notes` artifact). It authenticates
    with the `CLAUDE_CODE_OAUTH_TOKEN` secret.
  - `checks` (release mode): `ci.yml`.
  - `version` (release mode): bumps every version location, commits
    `chore(release): vX.Y.Z`, tags it and pushes `main` and the tag
    atomically. This is the only job that bumps.
  - `publish` (release and resume mode): creates the GitHub Release with the
    inspector's notes unless it already exists, then dispatches `release.yml`
    and `publish.yml` for the tag. It never bumps.
- `release.yml` (`Release`) is generated by dist 0.33.1 from
  `dist-workspace.toml` and kept unmodified, so `dist plan` keeps guarding it
  against drift. Dispatched with the tag, it builds the binaries and installer
  and uploads them to the existing GitHub Release.
- `publish.yml` (`Publish`) publishes to crates.io (`CARGO_REGISTRY_TOKEN`
  secret) and PyPI (`PYPI_TOKEN` secret, API token auth) as separate jobs.
  Each skips a version that is already published, so re-running is safe. Its
  `registry` input (`all`, `crates`, `pypi`) limits a manual dispatch.

## Recovering a failed release

Once `version` has pushed the tag, the version exists. Never bump again, and
never delete or move a pushed tag.

- **Before the tag was pushed** (`gate`, `inspect`, `checks` or `version`
  failed): fix the cause on `main`; the next push or a new dispatch of
  `Release (Auto)` releases from scratch. "Re-run failed jobs" also works.
- **`publish` failed** (GitHub Release not created, or a dispatch failed):
  "Re-run failed jobs" on that run. Only `publish` runs again; it keeps an
  existing GitHub Release and its notes, and dispatches both workflows.
- **A new dispatch on a tagged HEAD without a GitHub Release** goes straight
  to `publish` (`resume` mode), which cannot recover the inspector's notes
  from the earlier run and stops with an instruction. Either re-run the failed
  `publish` job of the run that pushed the tag (its `release-notes` artifact
  is kept), or create the release by hand and dispatch again:

  ```sh
  gh release create vX.Y.Z --verify-tag --title vX.Y.Z --notes-file notes.md
  gh workflow run auto-release.yml --ref main
  ```

  When the GitHub Release exists, the dispatch does nothing; start the
  missing workflows directly:

  ```sh
  gh workflow run release.yml --ref vX.Y.Z -f tag=vX.Y.Z
  gh workflow run publish.yml --ref vX.Y.Z            # -f registry=crates|pypi
  ```

- **`publish.yml` failed**: "Re-run failed jobs". A crate or PyPI file
  already published is skipped.
